# 音频延迟测试

浏览器里测量音频链路延迟的页面：播放一段短促的声音，用麦克风把回声收回来，算出「播放 → 麦克风收到」的时长，并判断这台设备能不能看视频、能不能打游戏。

## 功能

- 输出设备与输入麦克风分别选择
- 以一台基准设备为参照，给出待测设备自己多出来的延迟
- 测量后自动复核，链路中途变化时不给结论
- 深色与浅色两套主题

## 环境要求

- Node.js 与 pnpm
- 支持 AudioWorklet 的浏览器：近年版本的 Chrome、Edge、Safari
- 麦克风权限；测量时页面会发声，先把系统音量调小

## 运行

```bash
pnpm install
pnpm dev
```

打开 `http://localhost:5173`。麦克风只在 HTTPS 或 localhost 下可用。

## 使用

1. 选一台基准设备（内置扬声器或有线耳机最稳）与一支麦克风，点「开始校准」。
2. 校准完成后把输出换成待测设备，点「开始测试」。
3. 页面自动回基准设备复核一遍，通过后给出净延迟：待测设备延迟 − 基准设备延迟。
4. 换基准点「重新校准」。校准结果只保存在内存里，刷新即失效。

## 结论怎么看

- 50 毫秒以内：看视频、打游戏都没问题
- 50 到 150 毫秒：看视频没问题，打游戏会慢半拍
- 150 毫秒以上：连看视频都能看出对不上

## 为什么这样设计

- **先测一台基准设备**：延迟由整条链路决定——系统缓冲、设备、空气，换一个输出设备，整条链路的数字就变了。先量一台延迟最小的设备当参照，再量待测设备，两个数相减，剩下的才是这台设备自己的部分。
- **每次都要复核**：测量期间链路如果变了（换设备、系统重新协商缓冲），数字就没有意义；所以出结论前会回基准设备再测一遍，两次对不上就整轮作废重来。
- **全程只用一支麦克风**：换麦克风等于换链路，基准随之失效。
- **结果不落盘**：链路状态会变，上一次的基准对下一次没有意义。

## 注意

- 测量时页面会发出声音，先把系统音量调小
- 蓝牙设备每次重新连接都会重新协商缓冲，反复测量可能相差 ±20 毫秒
- 换过输出设备之后，基准那一侧的延迟会变，页面可能提示「链路不稳定」，重新校准一次即可
- 测量全部在本地完成，不上传任何数据

## 项目结构

- `src/audio/` 发声、录音分析与设备访问
- `src/hooks/` 测量流程状态机、主题、数字滚动
- `src/lib/` 阈值与刻度
- `src/components/` 刻度尺、判定胶囊、设备选择器、背景声场
- `src/App.tsx` 界面
